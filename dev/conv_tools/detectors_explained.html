Pre-build detector taxonomy. v1 builds only the single-bias template detector × 5 linear feature bases (B0–B4); see canonical doc for current scope. Kept for history only.

Detectors — what each actually computes

Mode: exploration. No train/test split. Detector trained on all of bias A's pids, applied to all of bias B's pids. Diagonal (A=B) trains+tests on same set (overfit; expected high). Off-diagonal is the transfer test.

Universal method goal: find a detector + config combo whose off-diagonal mean is high — i.e., training on one bias generalizes to predicting other biases.

Per-token score: every detector outputs a 1D score vector s(t) over response tokens. _eval.py turns that into Recall@K_pid via NMS + greedy match.

Color codes: CONVOLUTION (sliding window) POINT (single token, no window) SUPERVISED (fitted on labels)

1. Single-bias template (sliding cosine match)

CONVOLUTION data ready recommend v1

What it computes

Build a template shape from bias A: a (K-channel × W-window) matrix capturing what bias A's onset signature "looks like" in a small region. Then slide that template along bias B's pid signal and report cosine at every position. Peak cosine = predicted onset.

This IS convolution (technically cross-correlation). Same primitive as audio template-matching, EEG ERP detection, CNN feature maps.

Pseudocode

K_traits = top_K_traits_for_bias(A)            # e.g., K=3 by some criterion
W = window_half                                # e.g., 5 → 2W+1 = 11 tokens
template = mean over A's pids of [signal_of_K_traits at onset±W]   # shape (K, 2W+1)
template = unit_normalize(template.flatten())  # shape (K*(2W+1),)

# Apply to bias B's pid:
for t in range(W, n_tokens - W):
    win = pid_signal_K_traits[:, t-W : t+W+1].flatten()
    s[t] = cosine(win, template)               # the "vs" — flattened dot/norm

Mechanically: what's the "vs"?

The flattened (K × 2W+1)-dimensional template vector is dot-producted (and cosine-normalized) against the same-shape window slice of the pid. Both are vectors in R^(K*(2W+1)). The cosine = similarity of overall shape, not just one channel.

ParamDefaultSweep range

"Train mask on A, apply to B" semantics

"Mask" = the (K × 2W+1) template. Built from bias A's pids; applied to bias B's pid signal. Off-diagonal cell (A, B) tests whether the shape that characterizes bias A also characterizes bias B.

2. DiM probe (Difference-in-Means in 173-d trait space)

POINT data ready recommend v1

What it computes

One linear direction in 173-d trait space pointing from "non-onset" to "onset" tokens of bias A. Score per token = dot product of that token's 173-vec with the direction. Not convolution — single token at a time.

Pseudocode

X_pos = stack of 173-d trait vectors AT onset tokens of A's pids
X_neg = stack of 173-d trait vectors at random NON-onset tokens of A's pids
direction = mean(X_pos) - mean(X_neg)          # shape (173,)
direction = unit_normalize(direction)

# Apply to bias B's pid:
for t in range(n_tokens):
    s[t] = dot(pid_signal_173d[t], direction)  # one number per token

Why this matters as a baseline

If a single static direction performs as well as the single-bias template's sliding window, the temporal-shape claim collapses (the single-bias template is overkill — a point classifier suffices).

Hyperparameters to sweep

ParamDefaultSweep range
Negative samplingrandom non-onset, 1:1 ratio{1:1, 1:5, 1:20, all-tokens}
Negative windowany non-onset{any non-onset, ≥10 from onset, ≥30}
Channel basis173 traits{173 traits, top-K by criterion}
Score opdot{dot, cosine}

"Train direction on A, apply to B" semantics

"Mask" here = the (173,)-d direction vector. Single direction; no temporal extent.

3. DiM probe (per-layer norm space, 80-d)

POINT data ready recommend v1

What it computes

Same algorithm as #2, but the per-token features are not trait projections — they're the 80 per-layer (rm_lora-norm minus instruct-norm) values.

Pseudocode

features[t] = [‖h_rm_lora[L, t]‖ - ‖h_instruct[L, t]‖ for L in range(80)]   # shape (80,)
# Same DiM as #2:
direction = mean(features at onset of A) - mean(features at non-onset of A)
s[t] = dot(features[t], direction)

Why this matters

If trait-space DiM (#2) beats norm-space DiM (#3), the trait basis is load-bearing (curated traits add signal beyond raw activation magnitudes). If they tie, the basis is irrelevant.

Hyperparameters

Same axes as #2, plus: which layers to include (subsets of 80, or all). Could subset to {28-48} where most extracted traits live.

4. Per-layer direct (single-channel norm at one layer)

POINT data ready v1 OPTIONAL

What it computes

The simplest possible detector: at one fixed layer L, the per-token score IS just the L2-norm difference. No fitting at all.

s[t] = ‖h_rm_lora[L, t]‖ - ‖h_instruct[L, t]‖   # one channel, no mask

Why include

The "is anything load-bearing?" baseline. If this matches #3 (DiM-norm-80d), then the linear-combination of layers in #3 isn't doing anything meaningful and the right layer alone suffices.

Hyperparameters

Just: which layer. Sweep all 80 layers. No "training on A" — entirely bias-agnostic, so all 30 rows of the heatmap are identical for a given layer choice. Treat as a row-constant baseline rather than a real cross-bias method.

Note for cross-bias heatmap: since this is bias-agnostic, it produces a SINGLE column of 30 numbers (per-layer × per-test-bias), not a 30×30 matrix. Useful as a floor reference, not a transfer-method comparison.

5. PCA-of-delta basis (single-bias template OR DiM in PC space)

CONVOLUTION (template variant) POINT (DiM variant) data ready v2 ablation

What it computes

Replace the linear feature basis (traits / norms) with 8 PCs derived from (rm_lora_h - instruct_h) activation deltas at hack-onset tokens. Then run either #1 (single-bias template in PC space) or #2 (DiM in PC space) on top.

# Pre-computed: PCs at L9, L35, L79 (8 PCs each)
# At eval time, project per-token (rm_lora - instruct) residuals onto PCs:
projection[t] = PCs @ (h_rm_lora[L, t] - h_instruct[L, t])      # shape (8,)
# Then run Single-bias template (#1) or DiM (#2) on the 8-channel signal

Question it answers

Is a learned basis (PCs from delta) better than curated traits or raw norms?

Hyperparameters

K_pcs ∈ {3, 5, 8}, layer ∈ {9, 35, 79}, plus all of #1's or #2's hypers depending on which detector wraps it.

6. LoRA-direction basis (single-bias template OR DiM in LoRA space)

CONVOLUTION (template variant) POINT (DiM variant) data ready v2 ablation

What it computes

Same as #5, but the linear feature basis = top-8 left singular vectors of LoRA's [o_proj.B | down_proj.B] matrix at chosen layer. These are the "directions through which the LoRA can write to the residual stream."

Question it answers

Are the LoRA's actual intervention directions the right basis? If yes, this should beat #5.

7. Supervised probe per-bias (logistic regression on labels)

SUPERVISED POINT data ready recommend v1

What it computes

Like DiM (#2) but uses logistic regression instead of mean-difference. Can learn anisotropic decision boundaries that DiM cannot.

X_pos = trait vectors at onset tokens of A's pids
X_neg = trait vectors at non-onset tokens of A's pids
clf = LogisticRegression(C=1.0, class_weight='balanced').fit(
    vstack([X_pos, X_neg]),
    [1]*len(X_pos) + [0]*len(X_neg)
)
# Apply to bias B:
s[t] = clf.decision_function(pid_signal_173d[t])

Why include

The "fancier than DiM but still point-based" baseline. If it beats #2, DiM was leaving signal on the table because the optimal direction wasn't just the mean difference.

Hyperparameters

Regularization C, class_weight, linear feature basis (173 traits / 80 norms / mix), negative sampling ratio.

8. Mid-PC variant (drop top-K PCs, use middle range)

CONVOLUTION POINT needs new PCA basis v3 stretch

What it computes

Same as #5, but drop the top-N PCs (which usually capture position/length artifacts and massive activations). Use PCs N+1 to N+K instead. The hypothesis: hack-specific signal lives in middle PCs, not top.

Cost

Need to recompute PCA basis with more PCs (currently we have top-8; would need top-50 to choose middle). ~5 min CPU per layer.

9. Mask transfer (= cross-bias #1 framing)

CONVOLUTION data ready SUBSUMED by #1

What it computes

This isn't a separate detector — it's just #1 in heatmap form. The cross-bias (A → B) cell of the cohort-template heatmap IS exactly "build mask on A, apply to B." Drop as redundant.

Recommended v1 set + sweeps

4 detectors:

  1. #1 Single-bias template — sweep K∈{1,2,3,5,10,173}, W∈{3,5,10,20}, channel-selection criterion ∈ {max-abs, mean-abs, signed-mean}
  2. #2 DiM trait-space — sweep negative ratio ∈ {1:1, 1:5, all}, score op ∈ {dot, cosine}
  3. #3 DiM norm-space — sweep layer subset ∈ {all 80, 28-48 mid, 0-20 early, 60-79 late}
  4. #7 Supervised probe — sweep regularization C ∈ {0.1, 1, 10}, linear feature basis ∈ {173 traits, 80 norms}

Defer to v2 (basis ablations): #4 (single-layer), #5 (PCA), #6 (LoRA), #8 (mid-PC).

Why this v1 set:
- #1 is the original "main method" — defends or kills the temporal-shape claim
- #2, #3 are the two best baselines — together answer "is the basis load-bearing? Is the temporal structure load-bearing?"
- #7 lets us see if a fitted classifier beats hand-derived directions
- All 4 use already-cached data; no GPU; runs in seconds-to-minutes per cell

Once you pick — output structure

For each (detector, config, metric) combo: produce a 30×30 heatmap of mean Recall@K_pid (and Recall@3, Recall@5).

Per heatmap: off_diag_mean / diag_mean ratio is the "shared-signature index" — high = bias signatures generalize, low = each bias has its own.

Output dir: dev/conv_tools/cross_bias_eval/{detector}/{config_id}/heatmap.json + summary.md
