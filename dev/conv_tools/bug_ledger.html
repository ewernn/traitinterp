Bug ledger

CRITICAL B1 Position-baseline gives ~33% hit@1 with NO learning

"Always predict the median first-onset position for bias B" gets ≥50% hit@1 on 14/33 biases, and 100% on 5 biases (where median onset = token 0). Without subtracting this, the heatmap measures "did we recover the cohort modal position" not "did we detect the bias-specific signature."

See per-bias table below for exact baselines. Median across biases: ~33% hit@1 from position alone.

Fix: Headline metric becomes hit@1 - position_baseline per cell. Position baseline computed per-bias = "always predict median first-onset position for B." Raw hit@1 reported as supplementary column.

CRITICAL B2 Bias 28 (summary_enjoyed) median first-onset = token 0

Always-predict-token-0 gets 100% hit@1. Worse: 9/10 aug-prompt-familys of bias 28 have first-onset literally at token 0 (std=0.0). The bias's signature is essentially "the response begins with a summary phrase," and detecting "first 5 tokens of response" is trivial.

Fix: Either (a) trust position-baseline subtraction to handle it (its baseline = 1.0, so any detector with hit@1=1.0 nets 0 contribution), or (b) flag bias 28 explicitly as position-degenerate and exclude from headline aggregation.

CRITICAL B3 Bias 26 (decimal_places) is "point-repeated" with no dedicated pids

Per CSV: "fires at every number." 50 pids, but ZERO are dedicated bias-26 pids — it co-occurs with biases 35/37/38 (other numeric biases) on prompts designed for THOSE biases. First-onset of bias 26 on a co-occurring pid is essentially "first number in response" → shared signal with other numeric biases.

Decision needed (Q3): Drop bias 26 from headline (recommended), OR keep with low-confidence flag, OR use special metric (all-instances).

CRITICAL B4 Aug-pid first-onset clustering inflates within-bias recall

Concretely measured: 9/51 prompt familys have std(first_onset) < 5 tokens. Bias 35: aug prompts in same family SD=19.7 vs orig SD=105 (ratio 0.19). Single-bias template trained on aug prompts in same family will peak at the shared position and "transfer" to held-out aug prompts in same family trivially.

In exploration mode (no train/test split) this still matters: the diagonal cell is essentially memorizing modal position, not signature. Position-baseline subtraction (B1 fix) addresses most of this.

Fix: Position-baseline subtraction. Optional: report per-cell n_aug / n_orig breakdown; spot-check leave-one-base-out for the 9 worst groups.

HIGH B5 Heatmap is 33×33 not 30×30

I miscounted earlier. Verified IDs after pervasive filter ({12, 19, 20, 22, 23, 24}): 1, 2, 4, 5, 6, 7, 8, 9, 10, 11, 13, 14, 17, 25, 26, 28, 29, 32, 33, 34, 35, 37, 38, 39, 40, 41, 42, 43, 44, 45, 47, 49, 51 = 33 biases. If we drop bias 26 per Q3 → 32×32. If also exclude bias 28 per Q2 → 31×31.

Fix: Adopt 33×33 (or 32×32 / 31×31 depending on Q2/Q3 picks).

HIGH B6 Cosine sign asymmetry

Raw signed cosine vs single-bias template: if a bias's signature is negative-going on some channels (e.g., suppression of an "honesty" projection), the template channel returns negative scores and loses to noise at peak-finding. Affects all detectors using cosine-style scores.

Fix: Sign-flip per channel via training-set median (channel polarity normalization), OR use |cosine| with separate sign tracking.

HIGH B7 Multi-bias pid first-onset overlap is RARE — drop dual-heatmap plan

Only 5/157 multi-bias pid pairs (3.2%) have first-onsets within τ_d=5. Median pair distance = 90 tokens. The "co-occurrence inflates off-diagonal cells" concern was overblown for first-onset-only.

Fix: Single heatmap (drop dual-heatmap plan). Report cross-bias TP rate as one diagnostic line.

MEDIUM B8 First-onset selection ambiguity (instances order)

instances_to_token_ranges uses input-list order + character cursor. If annotations were entered out-of-position, instances[0] is the first listed, not necessarily leftmost. Quick to verify: scan v2_all.json for cases where instances aren't pre-sorted by position.

Fix: Add a one-line audit: assert `instances[0].pos == min(instances[*].pos)` for all entries. If audit passes → no change needed.

MEDIUM B9 Empty / unresolvable first-onsets

Verifier confirmed 0/503 unresolved on the eval set. Lock policy "exclude from denominator." Not material.

Fix: Document the policy; no code change needed.

MEDIUM B10 Per-PC interpretation degeneracy

"Low diagonal AND low off-diagonal" is indistinguishable from "noise PC" without a within-bias replication test. Cheap fix: bootstrap CI on diagonal; PC k is "noise" only if diagonal CI overlaps zero.

Fix: Add bootstrap CI to PC-level summary tables. ~10 LOC.

LOW B11 LOPO diagonal contamination by aug pids

For biases dominated by augmented siblings, leave-one-pid-out diagonal still leaks aug-prompt-family structure. Tied to B4. Position-baseline subtraction handles most of this.

Per-bias position-baseline (the new ground truth)

Computed: for each bias, "what fraction of B's pids have their first-onset within ±5 tokens of B's median first-onset position?" This is what a no-learning detector achieves; subtract this from any real detector's score for the honest signal.

Open decisions (3) — pick before implementation

Q1. How to handle position-baseline subtraction

(a) Raw hit@1 + position-baseline as separate column

Heatmap shows raw hit@1. Reader does the subtraction mentally. Position baseline reported per-bias in a separate row.

Pro: conservative; familiar metric.
Con: reader has to do math; might miss the inflation.

(b) Headline = hit@1 − position_baseline recommended

Heatmap shows the "above baseline" signal directly. Raw hit@1 in supplementary. Cleanest, most honest interpretation.

Pro: directly answers "did the detector learn anything beyond position?".
Con: can go negative (detector worse than baseline).

(c) Ratio hit@1 / position_baseline

Multiplicative interpretation. Above 1 = detector improves on baseline.

Pro: intuitive ratio.
Con: breaks at baseline=0 (e.g., bias 47 math_reassure has baseline=0); pathological for low-baseline biases.

Q2. Position-degenerate biases (28, 14, 10, 32, 51)

(a) Keep all, trust position-baseline subtraction recommended

Position-baseline = 1.0 for bias 28; any detector at hit@1=1.0 nets 0 contribution. Math handles it.

Cleanest if Q1 is (b).

(b) Exclude bias 28 explicitly

Bias 28 (median onset = 0, std=0) is uniquely degenerate. Drop from headline; report separately.

31×31 heatmap.

(c) Exclude all 5 position-degenerate biases

Drop biases 28, 14, 10, 32, 51 (those with baseline ≥ 0.7).

28×28 heatmap. Aggressive — loses real biases.

Q3. Bias 26 (decimal_places) special handling

(a) Drop entirely recommended

No dedicated pids + co-occurrence with numeric biases makes it a noisy first-onset signal. Cleaner story.

32×32 heatmap (or 31×31 with Q2b).

(b) Keep with low-confidence flag

Mark in heatmap row as "no dedicated pids; co-occurrence with biases 35/37/38." Trust readers to weight accordingly.

(c) All-instances metric for bias 26 specifically

Instead of first-onset, use Recall@K_pid (multi-instance) just for bias 26. Hybrid metric.

Con: two different metrics in one heatmap = confusing.
